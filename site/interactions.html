What is Playwright? ▼
Playwright is an open-source automation framework developed by Microsoft. It supports Chromium, Firefox, and WebKit browsers, and allows you to write reliable end-to-end tests.
How do locators work in Playwright? ▼
Playwright locators are lazy — they don't execute immediately. They represent a way to find elements on the page. Common methods: getByRole(), getByText(), getByLabel(), getByTestId(), locator('css').
What is the difference between page.click() and locator.click()? ▼
page.click(selector) is the legacy approach. locator.click() is the modern approach and is more reliable. Locators auto-wait and auto-retry, making tests more stable.
How do you handle authentication in Playwright tests? ▼
Use storageState to save session after login, then reuse it across tests. Or use a beforeEach hook to log in before each test. For API-based auth, use request.post() to get a token.

Playwright Overview

Playwright enables reliable end-to-end testing for modern web apps. Features include: auto-waits, multiple browser support, network interception, trace viewer, and parallel test execution.

Locator Types

getByRole('button', { name: 'Submit' }) — by ARIA role
getByText('Hello World') — by text content
getByLabel('Username') — by label
getByPlaceholder('Enter name') — by placeholder
getByTestId('login-btn') — by data-testid
locator('css-selector') — by CSS

Common Assertions

toBeVisible() — element is visible
toBeHidden() — element is hidden
toHaveText('...') — text matches
toHaveValue('...') — input value matches
toBeChecked() — checkbox is checked
toHaveURL('...') — URL matches
toHaveCount(n) — n matching elements

Best Practices

✓ Use data-testid attributes for stable selectors
✓ Prefer getByRole for accessibility-first testing
✓ Never use hard-coded sleep() — use auto-waits
✓ Use page.route() to mock network requests
✓ Use storageState to avoid login in every test
✓ Run tests in parallel with multiple workers
